# SOA Glossary

| Term | Meaning in this project |
|---|---|
| Service | A unit of software responsible for a specific business capability, such as managing products or orders. |
| Service interface | The operations a service makes available to other parts of the system. |
| Service contract | A description of how to use an interface, including its inputs, outputs, and expected behavior. |
| Service consumer | A frontend or service that calls another service's interface. |
| Service provider | A service that offers operations for other parts of the system to use. |
| Loose coupling | Designing services so one service depends on another's interface, not its internal implementation. |
| Service composition | Combining multiple services to complete a business process, such as placing an order. |
| REST API | An HTTP-based interface that uses methods such as GET, POST, PATCH, and DELETE to work with resources. |
| Modular monolith | One application organized into modules with clear responsibilities and interfaces, deployed as a single unit. This is the architecture modeled by the starter project. |
| SOA | Service-Oriented Architecture: an approach that organizes software around distinct, reusable business services with defined interfaces. |
